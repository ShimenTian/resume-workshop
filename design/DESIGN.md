# 简历工坊界面与文件规格

当前产品为纯前端简历制作工具。使用者在浏览器中编辑简历，把可编辑文件保存在自己的电脑上，下次打开文件继续编辑。界面分别说明浏览器草稿、电脑文件和 PDF 的用途。

本轮界面参照本地 `jianli-studio` 项目的绿色风格与页面结构，保留“简历工坊”品牌、原有草稿和本地文件流程。以下页面与交互已经接入当前源码；本轮浏览器验收结果见文末。

## 视觉与布局

| 项目 | 当前规格 |
| --- | --- |
| 主色 | `#167d67`，用于主按钮、选中态和重点文字 |
| 正文 | `#172b28` |
| 页面与首屏 | 白色页面、淡绿首屏 `#eff7f2` |
| 分隔线 | `#e5ebe7` |
| 字体 | 系统无衬线，中文优先 PingFang SC / Microsoft YaHei |
| 首页标题 | 桌面 48–52px，手机 35px，较窄屏幕继续缩小 |
| 内容容器 | 最大 1200px，手机左右留白 20px |
| 圆角 | 按钮 7px，模板预览 9px，预览弹窗 15px |
| 图标 | Lucide 线性图标 |
| 动效 | 按钮与卡片反馈、首屏短距离淡入；遵循减少动态效果设置 |

首页采用左侧标题与操作按钮、右侧纸张预览的结构，下接四个功能入口、模板区和制作入口。纸张、模板卡片、预览弹窗和编辑器均使用真实 HTML 简历组件，不依赖模板截图展示正文。

编辑器采用顶部文件操作、左侧内容与样式工具、编辑表单、右侧 A4 预览的结构。支持适应画布、手动缩放，以及手机上的“编辑简历 / 实时预览”切换。手机首页折叠导航，模板采用双列，草稿列表改为单列。

## 页面和交互

| 页面 | 路由 | 已接入的交互 |
| --- | --- | --- |
| 首页 | `#home`，也是默认页面 | 制作简历、浏览模板、打开本地文件、制作指南；默认展示四款模板预设 |
| 模板库 | `#templates` | 六款预设、分类、文本搜索、收藏筛选、清空条件和无结果提示 |
| 我的简历 | `#resumes` | 按更新时间展示浏览器草稿；空白新建、打开文件、继续编辑、复制、确认移除与短时撤销 |
| 编辑器 | `#edit/简历标识` | 全部简历字段编辑、经历排序、版式和配色、实时预览、文件保存、PDF 打印说明 |

模板卡片的预览与收藏是独立按钮。预览弹窗展示放大纸张、版式介绍和色板；选择颜色后点击“使用这个模板”，所选版式与颜色一同进入新草稿。仅预览或换色不会创建简历。

分类、搜索和“我的收藏”共同作用于结果。搜索覆盖名称、描述与分类；空结果状态提供重置入口。收藏按目录预设记录，不改变现有草稿的版式、配色或正文。

等待草稿读取完成后再显示主界面。编辑标识不存在时，显示明确提示，并提供打开文件和返回“我的简历”的入口。

| 目录标识 | 预设名称 | 文档版式 | 默认主题色 |

| `minimal` | 留白 · 极简 | `classic` | `#303d39` |
| `business` | 秩序 · 商务 | `sidebar` | `#3e5970` |
| `creative` | 灵感 · 创意 | `modern` | `#a17b45` |
| `campus` | 初光 · 校园 | `modern` | `#387b73` |

## 内容与保存交互

首页四个功能入口为开始制作、打开简历、挑选模板和制作指南。编辑器中的指南提供静态填写建议，当前没有 AI 生成、自动润色或面试分析，也没有把固定示例标为 AI 生成结果。

“保存到电脑”打开保存弹窗，显示文件名、用途和两次编辑之间需要重新保存的说明。普通下载为默认入口；支持文件选择保存位置的浏览器另有“选择保存位置”按钮。错误直接显示在保存弹窗中，用户仍可选择普通下载。

普通下载仅表示已经发起浏览器下载；选择保存位置则在完成写入和关闭文件后提示保存成功。取消文件选择不自动下载。保存过程中禁用重复操作与弹窗关闭。

PDF 通过浏览器打印窗口导出，说明包括 A4、100% 缩放、关闭页眉页脚、开启背景图形和检查分页。预览与打印共用简历渲染组件；可编辑的 JSON 文件另行保存，以便下次修改。

浏览器暂存失败时，界面显示错误、重试入口和保存文件提示。存在当前草稿时提供离页提醒。读取失败不覆盖损坏缓存；移除草稿需要先成功更新缓存，失败时保留原稿。移除操作不触碰电脑上已经保存的文件。

## 数据和文件兼容

- 浏览器草稿保持 `resume-workshop:documents:v1` 存储键及 `{ version: 1, resumes: [...] }` 格式，界面调整不迁移或清空已有草稿。
- 姓名、求职意向、联系方式、简介、工作、教育、项目和技能继续使用原有字段；文档版式限于 `classic`、`sidebar`、`modern`，配色单独保存在 `accent`。
- 收藏使用 `resume-workshop:template-favorites:v1`，格式为 `{ version: 1, keys: [...] }`；读取时去重并筛除无效目录标识。收藏不写入简历文件，存储失败时仅保留当前页面状态并提示。
- `.resume.json` 和旧版 `.json` 文件使用同一校验流程，上限为 2 MiB。校验完成后以新 ID 加入草稿，打开失败不修改已有简历。
- 浏览器草稿最多 50 份，每类经历最多 20 条，保留现有字段长度和类型校验。缓存失败时当前内容仍可编辑、复制和保存文件。
- 数据按网站来源隔离，同一来源下不同子路径共用浏览器存储。当前按单编辑窗口使用，不提供跨窗口冲突合并。

## 运行与部署

默认通过 `npm run dev` 开发，`npm run build` 生成 `dist/`，`npm run preview` 检查构建结果。生产版本部署到静态网站即可，无需 Java、数据库或 API 代理。

页面采用 hash 路由，构建资源使用相对路径 `base: './'`，支持根目录与子目录静态托管。默认浏览器逻辑不上传简历，文件仅在使用者主动选择时读取。

此前 Java 服务和本地 H2 数据保留为可选历史实现。Java 存储接口默认关闭，开启旧 API 需要显式配置；当前界面不依赖该接口，改版不读取或修改原数据库。
